- **源数据**：`orign_pdf/围城.pdf`（368 页 / 300 DPI → 1632×2335） → `orign_pdf/pages/` → `orign_pdf/textlines/`

## 0. 读之前必须知道的四件事（都是对照口径问题，不是 OCR 问题）

### 0.1 对照文本与 PDF 不是同一版次

| | PDF（本次 OCR 源） | 围城.txt（对照） |
|---|---|---|
| 版权页 | `2005.9重印` | `2017` |
| ISBN | `7-02-002475-0` | `978-7-02-012789-4` |

正文一致，但**前置页（封面/书名/版权/CIP/目录）必然对不上** —— 那是版次差异、不是 OCR 错误。无法锚定的页在第 5 节列出并已排除。

### 0.2 🔴 对照文本的**脚注编码**与书上不同（最大的一处干扰）

| | 书上（OCR 看到的） | 对照 txt |
|---|---|---|
| 脚注标记 | `①②③④` | `[5] [6] [7] [8]`（全文连续编号） |
| 脚注正文位置 | 印在**该页底部**，紧跟正文 | 排在 `***` 之后 |

两者**文本顺序与标记写法都不同**，Levenshtein 会算成一大块替换 + 删除/插入。这不是识别错误，是**对照文本的编码方式差异**。
⇒ 本报告把 **无脚注页（315 页）** 与 **有脚注页（44 页）** 分开统计，并以**无脚注页**作为「正文识别准确率」的主口径。

### 0.3 🔴 印刷页码被当成正文行（会污染指标，也会污染 EPUB）

实测全书有 **367 行**识别结果是整行纯数字、**涉及 363 页**，其中 **363 行落在页面纵向 85% 以下（页脚区，中位 0.92）** —— 那就是每页底部印的**页码**被 det 检出来当成了一行正文；另有 4 行散落在正文区。

| | |
|---|---|
| 整行纯数字的文本行 | 367 行，涉及 363 页（约每页 1 行） |
| 位置 | **页脚区（y/H>85%）363 行** / 正文区 4 行 |
| 样例 | `004`→`1`、`005`→`2`、`006`→`3`、`007`→`1`、`009`→`1`、`010`→`2`、`011`→`3`、`012`→`4` |

对照文本不含页码，所以这些数字会**同时**制造两类伪差异：① 整行插入；② Levenshtein 把它们对齐到邻近汉字上（如 `围`→`1`、`钱`→`9`），被计成「汉字↔非汉字」。**它们不是识别错误。**
⇒ 本报告额外给出一个**剔除页码行后**的口径作为「真实识别质量」。

### 0.4 三个归一化口径

| 口径 | 处理 | 回答的问题 |
|---|---|---|
| **N1 严格** | 仅去掉空白字符，标点原样 | 交付物与原文的**字面**差距 |
| **N2 NFKC** | N1 + Unicode NFKC（全角→半角、`Ⅰ`→`I`、`①`→`1`、`…`→`...`） | 排除纯编码差异后还剩多少 |
| **汉字-only** | 只保留汉字（U+4E00–9FFF） | **真正读错的字**有多少 |
