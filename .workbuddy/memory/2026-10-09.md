### 🔴 最重要的一条：top2 归属从「文本反查」改成「det 下标」
- 旧做法：`pending[text].pop(0)` 把 rec 捕获结果按**文本**反查回产物行。同一页出现两次
  「你好」时谁挂到哪一行只能猜 —— 等于把 A 行的模型证据挂到 B 行的框上。
- 新做法：在 `TextRecognizer.__call__` 处**复现引擎自己的排序分批**
  （`indices = np.argsort(width_list)`、`rec_batch_num`），拿到「批次位置 → det 下标」，
  由 `CTCLabelDecode` 钩子按 FIFO 取走。**零额外推理、零猜测**。
  依据：`crop_text_regions` 按**框顺序**裁图 → rec 输入顺序 = det 顺序（链路已逐行读过源码确认）。
- 自检：每页断言 `len(kept) == len(lines)`，不等就**抛错**（记 `top2_error`），
  **绝不**退回文本匹配。
- `dropped_lines` 同理：bbox 直接取 `det_boxes[det_index]`，删掉了 `(text, score)` 池子
  和整个 `filter_by_text_score` 钩子（monkey patch 从 4 处减到 3 处）。
- 🔴 **验证不变式**：`lines[m].bbox == det_boxes[lines[m].det_index]`。
  产物行的 bbox 来自过滤后的框、`det_boxes` 来自过滤前的框，两道过滤只删不重排不改坐标
  ⇒ 两者必须逐值相等。**只要下标归位有任何偏差，这条必然失败** —— 这是本次最有力的验证。
- 产物新增 `lines[].det_index` / `dropped_lines[].det_index`，
  `PRODUCT_SCHEMA` 4 → 5。

## 《围城》OCR 准确率评测（jiwer 4.0）—— 2026-10-09 深夜

脚本 `scripts/ocr_accuracy_report.py` → 报告 `docs/ocr-accuracy-围城.md`（501 行，入库）。
对照文本 `orign_pdf/围城.txt`；评测工具 `jiwer==4.0.0`（已进 requirements，标注为"产线不依赖"）。

### 口径（三个坑必须先剥离，否则结论全错）
1. **版次不同**：PDF = 2005.9 重印 / ISBN 7-02-002475-0；对照 txt = 2017 / 978-7-02-012789-4
   ⇒ 前置页必然对不上，9 页无法锚定已排除。
2. **对照文本的脚注编码与书上不同**：txt 用 `[12]` 且脚注排在 `***` 之后；书上是 ①②③④
   且脚注印在该页底部 ⇒ 44 页脚注页的差异是**块级错位**，不是识别错误 ⇒ 单列，不进主指标。
3. 🔴 **印刷页码被当成正文行**（367 行，363 行在页脚 y/H>85%）⇒ 会同时制造"整行插入"和
   "页码数字↔邻近汉字替换"，污染所有对照指标 ⇒ 主指标是**剔除页码行后**的口径。
   这也是一个**产物缺陷**：页码会进入下游 EPUB 正文。

### 对齐方法（对照文本没有页码标记）
页内 25%/55%/80% 各取 30 字探针，从**单调游标**处向下找 ⇒ 反推该页在对照文本的起点。
🔴 **终点必须用"下一页的起点"**，不能用 `起点 + OCR 页长`：OCR 漏字会让该页真实占据的
参考区间**比 OCR 页长更长**，于是每个页尾凭空多出几处"删除"。
实测这一处改动：无脚注页删除 1366 → 867，CER 0.943% → 0.697%。

### 结果（315 页无脚注正文页，参考 212046 字）
| 口径 | CER | 准确率 |
|---|---|---|
| N1 严格（含页码行） | 1.007% | 98.99% |
| **N1 严格（剔页码行）** | **0.697%** | **99.30%** |
| N2 NFKC | 0.939% | 99.06% |
| **汉字-only** | **0.337%** | **99.66%** |

- 逐页：中位 0.725% / 90 分位 1.852% / 最差 4.643%（210/315 页 < 1%）。
- 差异归因（正文页，1477 字符）：**整段删除 867（58.7%）** > 插入 212 > **汉字↔汉字 178（真错字）**。
- 🔴 **漏掉的 867 个字符里 616 个是标点**：破折号 `—` **470 个（54%）**、引号类约 150 个。

## 讨论：OCR 准确率报告的问题定性（2026-10-09 深夜；**只做只读复核，未改任何文件**）

用户要求"先讨论、不执行"。以下结论全部有实证数据支撑（读 JSON / 读 rapidocr 源码 / 滑动窗口复算）。

### 结论：报告的三个数字方向对，但有两点写偏了
**① 破折号不是"漏了 470 个字"，是 CTC 把 `——` 塌缩成 `—`（结构性，非置信度）**
- 对照 txt：`—` 共 1282 个 = **638 组 `——`** + 6 个单 `—`
- OCR 产物：`—` 共 717 个 = **244 组 `——`** + **229 个单 `—`**
  ⇒ 638 组双破折号里 **394 组被吞成一个**。
- 机制：`resize_norm_img` 把行缩到高 48px（长行不降采样：1165px→1216px），
  一条 26 字的行 ≈ 152 个 CTC 时间步，`——` 约占 11~12 步。CTC 的"重复 token 合并"
  要求中间出现 blank 才能输出两个 `—`；纸面是一条连续横线，blank 大概率不触发 → 塌缩。
- **det 侧无责**：9587 个 det 框里没有"长横线框被丢"的迹象（w/h≥15 的 8365 个都是普通宽行）。

**② "最差页"清单被页边界估计噪声显著放大（报告未提示）**
- 滑动参考窗口实测：**31/315 页**平移后有改善，**偏移全为负（-2 ~ -10）→ 起点系统性偏右**。
- 尾部页改善巨大：page_284 3.04%→1.76%、page_215 2.78%→1.55%、page_262 2.05%→1.10%、
  page_244 3.35%→2.74%；总量口径 0.6965% → **0.6513%**。
- 根因：`align_pages` 用页内 25% 处探针外推页首；该探针**之前**的 OCR 丢字 → 外推起点偏右。
- 实证案例 page_244/245：`同事们全知道` 被判成「244 删除 + 245 插入」，实际是边界偏 ~6 字。
  ⇒ 报告"最差 10 页"必须标注"含对齐噪声"。

### 引号：小标记 + 行末位置
`‘` 182→89（-93）、`’` 184→128（-56）、ASCII `'` 0→29；而 `“` 2706→2706（**0**）、

## 修复评测统计问题 + 重出《围城》OCR 准确率报告（2026-10-09 深夜）

用户复核发现「最大问题是统计问题」（不是识别质量），点名两处：
- `page_285`（旧报告最差第 1，CER 4.643%）实际错误只有破折号类，**没有**明显的删除和插入；
- `page_093` 的 `insert 斜川` 在 PDF / txt / OCR json 里都不是问题（`斜川` 本就在对照文本里）。

### 根因（实证）
`scripts/ocr_accuracy_report.py` 的 `align_pages` 用**页内 25% 处 30 字探针反推页首**：
`start = 探针命中位置 − 探针在页内偏移`。该式隐含「OCR 页内偏移 == 参考偏移」——
OCR 只要在探针**之前**丢了字（破折号/引号是重灾区），反推的页首就**偏右**：
`page_093` 偏右 2 字（把 `斜川` 判成插入）、`page_285` 偏右 10 字（把整句
`事。你现在气平了没有` 判成插入）。全书 **31/315 页**存在可被平移改善的边界，**偏移全为负**。

### 修法
1. `_anchor_start()`：**直接锚定页首** —— 页面开头 48 字精确查找（长度 48→40→…→10 逐级回退），
   失败走 `rapidfuzz.fuzz.partial_ratio_alignment` 模糊兜底 + 页内中段 16 字吸附精修。
2. 终点仍 = 下一页起点（不重叠划分）。
3. 新增 `slide_check()`：把每页参考窗口平移 ±24 字，看 CER 能否再降 —— 作为对齐质量硬指标。
4. 新增 `front_matter_pages()`：按**书自己的页脚页码**找「最长连续 +1 序列」定正文范围，
   前置页（封面/版权/CIP/序）单列不参与指标（page_003 版次不同、page_006 参考段混入目录）。
   正文 = `page_009` … `page_367`。
